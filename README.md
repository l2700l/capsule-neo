# Capsule Neo Proxy

Модульный HTTP-прокси и mock-сервер для исследования API устройства Capsule Neo.

Проект предназначен для перехвата, записи, анализа и воспроизведения запросов устройства. Цель - постепенно изучить протокол и заменить обращения к оригинальному серверу собственными обработчиками.

## hardware_commands.md

Отдельно вынесены типы команд, которые принимает колонка, были вытащены из разговора с колонкой в сценарии "обычного использования"

Из прошивки получилось вытащить: send_event_data (event, callback_data), send_event (event, callback_data), speed_test, reminder, scenario_step (text, event, callback_data), enter_flowmode (callback_data), flowmode_sound (url), bg_music, flowmode_bg_music (url, count), cancel_notification, reminder_cancel, playlist (eof, seek_track, seek_second)

## Зависимости

Для работы проекта необходимы:

- **Python 3.11+**
- **Docker Compose** — для запуска Nginx.
- **FFmpeg** — для конвертации аудио в Ogg Opus при использовании локального TTS.
- **PyTorch и NumPy** — устанавливаются автоматически из `requirements.txt` и используются движком Silero TTS.

### Установка FFmpeg

**macOS (Homebrew):**

```bash
brew install ffmpeg
```

**Ubuntu / Debian:**

```bash
sudo apt update
sudo apt install ffmpeg
```

Проверьте установку:

```bash
ffmpeg -version
```

FFmpeg должен быть доступен через `PATH`. Без него локальная генерация речи не сможет преобразовать аудио в формат, используемый колонкой.

## Запуск

### 1. Запустить Python-сервер

```bash
python3 -m venv .venv
source .venv/bin/activate
pip3 install -r requirements.txt
cp .env.example .env  # необязательно
python3 -m capsule_proxy
```

По умолчанию сервер слушает `0.0.0.0:8082`.

### 2. Запустить Nginx через Docker Compose

Nginx используется для HTTPS и маршрутизации запросов устройства между основным сервером и WebSocket-сервисом. Сам Python-сервер запускается непосредственно на хосте, без сборки Docker-образа.

Сертификаты должны находиться в каталоге `certs/` в корне проекта.

Запуск Nginx:

```bash
docker compose up -d
```

Остановка:

```bash
docker compose down
```

В конфигурации Nginx для доступа к Python-серверу, запущенному на хосте, используется `host.docker.internal`. На Linux для этого может потребоваться добавить в сервис Nginx настройку:

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

Основной сервер слушает порт `8082`, WebSocket-сервис - `8083`

### 3. Перенаправить DNS-записи устройства

Чтобы устройство обращалось к локальному серверу вместо оригинального, настройте DNS-переопределение на роутере.

Создайте локальную DNS-запись:

| Домен | Адрес |
|---|---|
| `vc.go.mail.ru` | IP-адрес компьютера с Nginx |

Укажите локальный IP компьютера, на котором работает Docker, например `192.168.1.100`. Используйте фактический адрес своей сети.

После этого устройство должно получать локальный IP для `vc.go.mail.ru`, а HTTPS-соединение на порт `443` будет принимать Nginx.

Названия и расположение настроек DNS зависят от прошивки роутера. Ищите функции вроде *DNS Rebinding*, *Local DNS*, *DNS Host Mapping* или *Static DNS*. Если роутер не позволяет создавать записи для отдельных доменов, можно использовать локальный DNS-сервер, например AdGuard Home или dnsmasq.

**Важно:**

- Компьютер с сервером должен иметь постоянный локальный IP либо DHCP-резервацию на роутере.
- DNS-переопределение действует только на устройства, использующие настроенный DNS-сервер.
- Если устройство использует DoH/DoT, собственные DNS-серверы или закреплённые IP-адреса, одного переопределения на роутере может быть недостаточно.

Положите mp3 файлы в `radio/` либо укажите путь через переменную окружения `CAPSULE_TEST_MP3`.

## Маскирование заголовков

По умолчанию чувствительные HTTP-заголовки маскируются в логах и генерируемых командах `curl`.

Чтобы отключить маскирование для локальной отладки:

```bash
CAPSULE_REDACT_SENSITIVE_HEADERS=0 python -m capsule_proxy
```

Настройка влияет только на логирование и вывод команд `curl`, а не на заголовки, отправляемые оригинальному серверу.

Не публикуйте логи и сохранённые запросы без проверки: они могут содержать токены, cookies и другие конфиденциальные данные.

## Добавление HTTP-маршрутов

1. Добавьте функцию-обработчик в соответствующий модуль каталога `capsule_proxy/handlers/`.
2. Зарегистрируйте маршрут в `capsule_proxy/routes.py`.
3. Укажите метод, скомпилированное регулярное выражение пути, ожидаемый тип содержимого и функцию-обработчик.

Обработчик возвращает JSON-совместимый объект либо кортеж:

```python
(status, response_object, response_type)
```

Поддерживаемые типы ответа в текущей архитектуре: `json` и `msgpack`.

## Текущее состояние

| Возможность | Статус | Примечание |
|---|---|---|
| Модульная структура проекта | Частично готово | Код разделён на конфигурацию, HTTP-утилиты, маршруты и обработчики |
| Запуск HTTP-сервера | Реализовано | По умолчанию порт `8082` |
| Маскирование чувствительных заголовков | Реализовано | Есть настройка отключения через переменную окружения |
| Mock-обработчики настроек | Частично готово | Необходимо проверить поведение и ответы каждого маршрута |
| Проксирование `/phrase/create/...` и `/phrase/add...` | Перенесено | Запросы передаются на оригинальный сервер, ответы возвращаются устройству. Сохраняются данные обмена для последующего анализа |
| Проксирование результатов `/phrase/result` | Перенесено | Требуется проверить обработку ответов и замену URL |
| Проксирование `/stream` | Перенесено | Требуется проверить длительность соединения и запись потока |
| Локальная раздача `/radio/*.mp3` | Перенесено | Использует mp3 файлы из `radio` |
| Ответ для `/device/timezone/info` | Перенесено | Возвращает данные часового пояса |
| Сохранение тел запросов для `curl` | Реализовано | Полное тело сохраняется в бинарный файл, команда curl ссылается на него через --data-binary @файл |
| WebSocket | Реализовано | Используется для отправки бинарного сообщения-триггера, после которого колонка запрашивает настройки по HTTP |
| Полная совместимость с оригинальным сервером | Не подтверждена | Необходимо сравнить маршруты, тела запросов и ответы с исходной реализацией |

## План дальнейшей работы

1. **Завершить восстановление HTTP API:** проверить, все ли запросы колонки обнаружены и реализованы, найти пропущенные маршруты и изучить их назначение.

2. **WebSocket:** изучить формат сообщений, последовательность обмена и условия поддержания соединения. Базовая отправка бинарного сообщения-триггера уже реализована. Дальнейшая задача — определить, какие ещё функции WebSocket необходимы для полноценной замены оригинального сервера.

3. **Проверка совместимости:** сравнить поведение модульного сервера с оригинальным скриптом и реальными ответами сервера Capsule Neo, выявить расхождения и проверить работу основных сценариев.

4. **Реализовать машину состояний:** перейти от статических заглушек к согласованному поведению сервера. Учитывать текущее состояние устройства, изменения настроек и последовательность запросов, чтобы ответы зависели от предыдущих действий и отражали актуальное состояние колонки.

5. **Собрать полную таблицу ответов голосового ассистента:** исследовать запросы и ответы для различных команд, сценариев и ошибок. Зафиксировать форматы сообщений, возможные состояния и последовательности обмена, необходимые для полноценной замены оригинального сервера.

6. **Постепенно отказаться от оригинального сервера:** на первом этапе проксировать неизвестные и ещё не реализованные запросы, сохраняя их для анализа. По мере изучения протокола заменять проксирование собственными обработчиками, пока основные функции колонки не станут работать автономно.

## Важное замечание

Проект начинался как самописный исследовательский сервер для изучения API Capsule Neo.
Текущая версия ещё не воспроизводит всё поведение устройства: некоторые тестовые ответы упрощены или обезличены. Нельзя считать поведение устройства полностью воспроизведённым, пока не проверены все необходимые маршруты и WebSocket-обмен.

Сохранённые запросы и ответы следует считать исследовательскими данными: перед публикацией необходимо удалить токены, cookies, идентификаторы устройства и другую приватную информацию.
